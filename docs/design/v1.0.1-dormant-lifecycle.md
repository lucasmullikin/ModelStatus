# v1.0.1 — Approved-Server Dormant Lifecycle & Auto-Revive

**Status:** DRAFT → Codex audit → LOCK → implement
**Created:** 2026-06-01
**Scope decision (user, 2026-06-01):** Re-mount previously-approved servers only. **No** background LAN/Tailscale scanning. The on-demand Discovery scan is untouched, so the App Store privacy claim ("discovery scan never runs in the background") stays accurate.

---

## Problem

Today every configured server stays in the menu as a red "Unreachable" row forever when it's down, and there's no notion of a server that was approved, went away, and came back. The user wants:

1. Servers show their live state (generating / active / idle) while reachable.
2. When a server goes unreachable, it shows as **dormant** (greyed, "last seen Xh ago") for **24h**.
3. After 24h unreachable it **disappears** from the visible list (soft-forget).
4. A previously-approved server that **comes back online auto-reappears** — no re-approval, name + auth restored.

## Key reframing (why this needs no background scan)

"Auto re-mount an approved server" = **monitoring a known URL**, which the app already does every poll cycle. It is *not* discovery (a /24 sweep + Tailscale enumeration). So:

- A dormant server is still in config and still polled at the normal interval → the instant it answers, it flips back to active. That covers the common case (down minutes/hours).
- A soft-forgotten (archived) server is hidden from the menu but its **specific approved URL** is re-checked at a low interval. If it answers, it's silently revived. This is the same *class* of network activity as existing dormant polling — re-GETting one URL the user explicitly approved — never a network scan.

**Privacy invariant preserved:** no LAN/Tailscale enumeration is ever added to a background path. `Discovery.scan()` remains on-demand only.

## State model

Add three backward-compatible fields to `Instance` (all `decodeIfPresent` with defaults so existing config JSON loads unchanged):

```swift
struct Instance {
    var id: UUID
    var name: String
    var url: String
    var kind: ProviderKind
    // NEW:
    var addedAt: Date            // default = now at add time
    var lastSeenReachable: Date? // set on each reachable poll; nil = never reached
    var archivedAt: Date?        // nil = visible (active/dormant); non-nil = soft-forgotten
}
```

**Reference time** for lifecycle math: `lastSeenReachable ?? addedAt`. (A freshly-added server that's never been reachable starts its dormant clock from when it was added, so a ghost URL still ages out.)

### Lifecycle (evaluated per poll cycle, in Monitor, after each instance's check)

Let `ref = lastSeenReachable ?? addedAt`, `now = Date()`, `down = now - ref` (clamped ≥ 0 for clock skew).

| Condition | Transition | Menu |
|---|---|---|
| reachable | `lastSeenReachable = now`; if `archivedAt != nil` → `archivedAt = nil` (**revive**) | normal row |
| unreachable, `archivedAt == nil`, `down < 24h` | none (**dormant**) | greyed row: "name · dormant, last seen Xh ago" |
| unreachable, `archivedAt == nil`, `down >= 24h` | `archivedAt = now` (**archive**) | hidden |
| `archivedAt != nil`, reachable on revival check | `archivedAt = nil`, `lastSeenReachable = now` (**revive, silent**) | reappears as normal row |
| `archivedAt != nil`, `now - archivedAt > 30d` | **hard delete** (config + Keychain) | gone permanently |

Flapping is self-correcting: any reachable poll resets `lastSeenReachable`, so a server that blips down/up never prematurely archives.

### Constants (single source, `LifecyclePolicy` enum)

```
dormantWindow    = 24h    (86_400 s)
archiveRetention = 30d    (2_592_000 s)
revivalInterval  = 600 s  (how often archived URLs are re-checked)
```

A single Settings toggle `autoManageDormant` (default **true**) disables the whole lifecycle (servers behave as today: stay visible, never auto-prune) for users who want manual control. Addresses the "don't surprise users by deleting servers" concern from ticket #3.

## Polling changes (`Monitor`)

- Partition each cycle: **visible** instances (`archivedAt == nil`) polled every `pollInterval` (unchanged). **Archived** instances polled only when `now - lastRevivalCheck >= revivalInterval`.
- After collecting `[ServerStatus]`, compute lifecycle transitions and apply them via a single `MainActor.run` batch into `ConfigManager` (persisted). Reuses the existing generation-guard so a stale cycle can't write transitions.
- The status stream still emits the **visible** set for the menu; archived servers are excluded from the emitted array.

## Persistence / `ConfigManager`

- New transactional methods, each `save()`-guarded with rollback like the existing ones:
  - `markReachable(id:at:)` — sets `lastSeenReachable`, clears `archivedAt`.
  - `archiveInstance(id:at:)` — sets `archivedAt`.
  - `reviveInstance(id:at:)` — clears `archivedAt`, sets `lastSeenReachable`.
- Hard delete reuses existing `removeInstance(id:)` (already cleans Keychain).
- Batched variant `applyLifecycle(_ transitions:)` to coalesce one save per cycle instead of N.

## Menu changes (`AppDelegate`)

- Visible reachable → existing rendering.
- Visible unreachable (dormant) → `NSMenuItem` with dimmed attributed title + relative "last seen" via existing `Formatters.elapsed`.
- Archived → not rendered.
- Compact mode mirrors the same dimming.

## Migration

Existing `~/Library/Preferences/com.lucasmullikin.ModelStatus.json` has no new fields. On decode: `addedAt` defaults to now, `lastSeenReachable`/`archivedAt` default nil. First reachable poll backfills `lastSeenReachable`. No destructive migration; downgrade-safe (older app ignores unknown keys).

## Edge cases

- **Clock moved backward:** clamp `down`/retention deltas to ≥ 0; never archive on negative.
- **Never-reachable ghost (manual bad URL):** archives 24h after `addedAt`, hard-deletes after 30d → free cleanup of the ghost problem in ticket #3.
- **Auth header:** retained in Keychain through archive; reused on revive; deleted only on hard delete.
- **Sandbox (App Store build):** all paths are HTTP polling — no shell/Tailscale — so behavior is identical sandboxed.
- **User manually removes dormant/archived server:** `removeInstance` works as today (and should also drop any in-memory revival timer).
- **All servers archived:** menu shows the existing empty/"no servers" affordance; revival polling continues.

## Privacy / App Store

No new background scanning. Revival re-check = HTTP GET to a specific previously-approved URL, same class as existing dormant polling. `APP-STORE-METADATA.md` privacy copy ("discovery scan is on-demand only") remains true — **no copy change, no re-review risk.**

## Test plan (TDD, pure where possible)

`LifecyclePolicy` is a pure function `classify(now:addedAt:lastSeenReachable:archivedAt:reachable:) -> Transition`. Unit-test the full truth table without Monitor/network:

- reachable revives an archived instance
- dormant boundary: 23h59m unreachable = dormant; 24h01m = archive
- archived + reachable on revival = revive
- archived + 30d = hard delete
- clock-skew (ref in the future) never archives
- never-reachable ghost archives from `addedAt`
- toggle off → always `.none`

Plus: ConfigManager round-trips new fields (Codable migration test), and a Monitor integration test that a visible-set emission excludes archived instances.
