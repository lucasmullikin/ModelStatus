## What Apple actually said, and what we did

### ① Guideline 2.4.5(vii) — "The app updates itself outside of the Mac App Store"

They attached a screenshot of the menu with **"Check for Updates…"** highlighted.

**Root cause.** The Review Notes we submitted claimed the sandboxed build skipped
the update check. That was not true of the code. The only guard was runtime —
`UpdateChecker.check()` returned early when `isAppStoreInstalled()`, which tests
for an App Store *receipt*. **App Review installs from the `.pkg`, which has no
receipt**, so the guard evaluated false on the reviewer's machine. The menu item
itself was never behind even that check.

**Fix (commit `3668bb0`).** Compile gate, not a runtime test. The whole
`UpdateChecker` unit, the launch-time check, the "Update available" submenu, the
"Check for Updates…" item, its actions, and the GitHub hosts in the
`isSafeOpenURL` allowlist are all `#if !MODELSTATUS_APP_STORE`.

**Proof — against the binary, not the source:**

| string | direct build | App Store build |
|---|---|---|
| `Check for Updates` | 1 | 0 |
| `Update available` | 1 | 0 |
| `api.github.com` | 2 | 0 |
| `releases/latest` | 1 | 0 |
| `brew upgrade --cask` | 2 | 0 |
| `githubusercontent` | 1 | 0 |

The Settings "GitHub" button is also hidden in the App Store build (commit
`64f06d0`) — that repo's Releases page serves a downloadable `.app`.

### ② Guideline 2.1 — App Completeness (delivered as a hardware demo-video request)

Their screenshot shows the entire app: one row, **"Local — Unreachable"**.

**Root cause.** `AppConfig.default` hard-coded an instance at Ollama's default
port. On a machine without Ollama that could only ever render as a red ✗, with
nothing explaining it and no next step.

**Fix (commit `64f06d0`).** Nothing is seeded. First launch probes **loopback
only** (`Discovery.probeLoopback`) and adopts whatever is actually running,
named "<Kind> on this Mac". If nothing answers, the menu says "No AI server
found yet", names the server kinds it looked for, and offers "Add a Server…"
and "How do I set this up?".

Loopback deliberately, not `Discovery.scan()`: a /24 sweep trips the macOS
local-network permission prompt and reaches other machines, so it stays behind
an explicit user action.

**Proof — verified by running the App Store `.app`:** from an empty config,
0 instances before launch → 1 after, `"Ollama on this Mac"`.

⏳ **Still owed:** a demo-video URL in App Review Information, plus a reply
correcting the hardware premise (see the draft below).

### ③ Guideline 5 — Legal (China deep-synthesis permitting)

> "the app's metadata includes the following references to ChatGPT and/or OpenAI: OpenAI"

**Decision: deselect China mainland** in Pricing and Availability. Apple asked
for two things — remove the metadata references *and* deactivate the
functionality in the China build. App Store Connect ships one binary to every
storefront, so "deactivate in China" would mean removing OpenAI-compatible
endpoint support for everyone. Deselecting China removes nothing and
misrepresents nothing.

⏳ **Still owed:** the availability change in App Store Connect.

## Draft — new Review Notes

> ModelStatus is a menu bar utility that monitors AI model servers over HTTP.
> It is software-only: there is no hardware, no device pairing, no companion
> accessory, and no sign-in.
>
> Exercising the app during review:
>
> 1. Launch from /Applications. A brain icon appears in the menu bar.
> 2. With no model server installed, the menu reads "No AI server found yet"
>    and offers "Add a Server…" and "How do I set this up?". This is the
>    intended empty state, not a failure.
> 3. To see it monitoring something, install any local model server (Ollama
>    from ollama.com is the quickest) and relaunch. The app probes this Mac on
>    launch and adds what it finds automatically.
> 4. Alternatively, Settings → Add and enter any HTTP URL. Servers that expose
>    only a /health endpoint work via the "HTTP Health" kind.
>
> Network activity, in full:
> - HTTP polling of the server URLs the user configures.
> - An on-demand local-network scan, only when the user clicks "Discover
>   Servers…" in Settings. Never automatic.
>
> This build performs no update checks of any kind. Following the 2026-06-09
> rejection under Guideline 2.4.5(vii), the entire updater is removed from the
> App Store build at compile time — the binary contains no update UI, no
> release endpoint, and no upgrade instructions.
>
> No telemetry, no analytics, no accounts, no external backend.
